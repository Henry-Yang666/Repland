# Repland V2 方案：日常自动执行，第一批已授权实施

日期：2026-10-16，Asia/Shanghai。状态：**核心方向及第一批四条流程已获用户授权实施；其余功能仍为后续候选。没有据此声称代码、测试或交付已经完成。**

本方案初稿回应“优化全部功能设定、提高 AI 执行权限、先生成再讨论”。后续用户已同意推荐方向并授权第一批实现；最新又明确撤销此前“本阶段不要大幅改动 UI”的限制，允许围绕自动安排自主重新设计。批准范围与历史 C01–C07 取代关系见 [第一批授权记录](AUTONOMY_PHASE1_2026-10-16.md)。主思路与术语已同步；283 条清单及逐条映射仍是当时的讨论快照，不能将其中全部远期建议当成已批准交付。竞品资料为初稿调研记录，未进行账号内实测。

## 1．推荐方向

**用户告诉 Repland 要达成什么、有哪些现实变化；Repland 自动维护一份可执行计划，用户需要时查看、纠正、暂停或撤销。**

日常路径改为：

> 说出事项或变化 → 助手直接完成允许的操作 → 查看一句结果 → 必要时纠正或撤销。

授权范围内的后台维护无需每次输入。任务创建、估时、分类、拆分、普通安排和重排，不再逐次要求“允许调用模型 → 阅读建议 → 采纳字段 → 查看草案 → 确认写入”。内部仍做校验、事务和版本记录，这些可靠性机制不应成为用户必经的审批步骤。

推荐默认提供一个“AI 自动安排”入口：首次清楚说明后启用，之后持续有效，随时可暂停。另保留“仅建议”作为可选行为，不恢复三种复杂用户人格/参与模式，也不要求每个功能分别授权。没有模型时仍可本地自动维护基本排程。

### 要解决的真实问题

- 用户已经说“帮我安排”，还要再次确认同一意图。
- 用户要先填写时长、类别、预计天数，系统才肯安排。
- 系统发现计划失效，却把“重新排序、重新估时、解决冲突”交还用户逐项处理。
- 每个错过的时段都变成待确认，形成额外的管理负担。
- 分类、优先级、不可避免、锁定、轨道、延期状态同时影响安排，理解成本过高。

## 3．新的十条核心原则

| 编号 | 建议规则 |
| --- | --- |
| R01 | 首次启用日常委托后，范围内的创建、估时、拆分和普通安排可以直接生效；不逐次索要同意。 |
| R02 | 用户明确表达的操作意图就是本次执行授权；能定位对象、理解范围时直接做，不重复问“是否确定”。 |
| R03 | AI 估计可以用于规划，保存来源和不确定性；用户事实、AI 推断、系统观察与实际执行分开。 |
| R04 | 重要程度与是否可移动分开；课程、真实约定和显式固定项受到保护，普通任务可自动调整。 |
| R05 | 自动维护优先局部修复，保持近期和手动安排稳定；不为微小分数变化反复重排。 |
| R06 | 用户只处理会改变承诺、越过授权边界或无法判断真实意图的少量问题；同一问题合并询问一次。 |
| R07 | 计划到点、计时结束和无人回应不等于完成、失败或用户延期；明确指令和有效执行证据可以直接更新结果。 |
| R08 | 自动操作有简短回执、可查原因和操作级撤销；执行前仍经过本地校验、原子提交、幂等及版本检查。 |
| R09 | 通知服务于行动，普通自动改动安静合并；错过时段不形成强制待确认债务。 |
| R10 | 自动化在明确的数据、运行和费用范围内执行；可一句话暂停；断网或模型失败仍保留本地能力。 |

## 4．AI 权限具体开放到哪里

### 4.1 默认可自动执行

以下行为在用户启用日常委托且无重要歧义时，不要求打开草案页。只有安排具体时间需要已采用的可用时间边界；创建、分类、估时、拆分、查询和摘要不要求先配置作息：

| 行为 | 默认权限 | 结果呈现 |
| --- | --- | --- |
| 从已发送的事项描述创建任务，防止重复提交 | 自动创建；按稳定身份/同次操作去重，不能因语义相似合并两件真实任务；不把尚未发送输入、引用范文或示例当指令 | “已记下 3 项并安排；撤销” |
| 分类、标签、估时、拆步骤 | 自动填写 AI 建议字段，保留原始输入与用户明确字段 | “预计约 45 分钟”，点开可改 |
| 新任务排进空档，普通任务局部改期 | 直接更新生效计划和提醒 | 安静的变更摘要，按需展开 |
| 提前结束、用户说延长、加入临时事项后的重排 | 自动维护剩余柔性工作 | 说明受影响的少数事项 |
| 错过时间后的重新安排 | 按当前可见剩余工作重新分配，不复制每个旧时段，不制造真实延期事件 | “已重新安排后续工作，之前的实际结果未记录” |
| 周期任务的生成、日常滚动及缓冲 | 按用户已建立的系列规则自动维护 | 系列详情和单次实例可修改 |
| 当日摘要、明日安排、画像统计与必要的 AI 描述 | 在同一持续授权和预算内自动更新，无变化不调用模型 | 一张简短摘要，不要求逐条确认 |
| 根据已确认偏好调整新估时/分段 | 自动应用到系统规划值，不覆写用户原始估计 | 来源可查，可撤销这次调整 |

### 4.2 用户一句话即可直接执行

| 用户表达 | 助手执行 |
| --- | --- |
| “物理报告写完了。” | 定位报告，直接完成，追加用户声明来源；清理未来安排、重新利用空档。 |
| “听力做了一半，明天接着来。” | 记录用户明确的部分进度，更新剩余安排；不要求填写完成内容和耗时表单。 |
| “今天算法课停课。” | 建立当天课程例外，保留原模板；这句话已授权当天变更，无需再弹一次批准。 |
| “把跑步挪到周末。” | 明确对象后移动本地安排；不改成已失败，也不改其他任务的真实截止。 |
| “以后每周三复习物理。” | 建立周期规则；默认从最近一次将来的周三开始，其余缺项按估计处理，回执说明。 |
| “开始这个／暂停／结束这一轮。” | 操作计时与执行记录；存在另一个活动会话时只询问如何交接。 |
| “这条不用做了／删除这条。” | 取消或放入可恢复回收站；若对象明确，不重复确认。 |
| “今晚不要再调整我的计划。” | 暂停今晚自动调整；保留任务、原计划和正常提醒，回执显示恢复时机。 |
| “撤销刚才的安排。” | 撤销对应操作及其连带排程，不要求用户逐个找到时段复原。 |

指代不清、语言否定不确定、系列范围对结果有实质差异时，才用一个简短问题澄清。比如讨论了多个任务后说“把它删了”，不能随意选一个。用户明确说“从此以后”或“仅今天”时直接沿用该范围，不再让他填一遍范围表单。

### 4.3 保留的少量决策

- 现有可用时间确实无法满足真实截止或多个明确承诺，需要决定牺牲哪项、是否使用额外弹性时间。
- 系统想越过用户固定课程、睡眠底线或显式锁定，而用户没有明确要求改变这条边界。
- 清空全部历史、不可恢复删除、换数据接收服务或接入新数据来源。
- 后续对外发消息、预约、支付、通知他人等超出当前个人计划权限的动作，按单独授权处理；不为本轮功能优化提前引入这些集成。

明确指令已经包含对象与取舍时，不以“重要”为理由重复问一次。普通本地取消、归档和可恢复删除使用回执＋撤销，不统一套上破坏性操作弹窗。

### 4.4 一个用户入口，内部记录范围

用户只需理解“AI 自动安排：已开启／暂停”，高级设置才展示范围。内部记录允许动作、可用/弹性窗口、固定项、选定数据来源、费用预算和到期条件；不把这些扩成二十个首次启动必填开关。

用户说“只替我整理这周”“这个项目交给你安排”“今晚赶报告可以晚一小时”时，系统可以创建有期限的授权或例外并直接执行。偏好、授权、执行事实分别保存；模型在文件或网页中读到的“忽略限制”不构成用户授权。

## 5．全部功能模块的新设定

| 模块 | 推荐的新行为 | 用户通常需要做什么 |
| --- | --- | --- |
| 首次使用 | 先录入事项；采用一次可编辑作息模板，课表可后补。模板标为建议，用户采用后才成为自动安排边界。 | 选择/说出基本可安排时段并启用自动安排一次；可以跳过，先保存事项。 |
| 模型配置 | 保留 BYOK，高级设置提供服务预设和连接测试；正式构建支持同一能力。若后续提供托管模型服务，另定成本与服务方案。 | BYOK 用户仍需填密钥一次；不能把这一技术门槛声称已消除。 |
| 统一输入 | 文字、语音、分享、文档经同一意图入口处理，支持边说边改和连续上下文。 | 说事情，不先选择“新增/排序/重排/复盘模式”。 |
| 任务创建 | 默认保存并自动安排；“先记着／不要排”进入收集箱。没有时长可用标记为估计的规划值。 | 只纠正误解；不必先补齐分类、时长、天数。 |
| 任务组织 | 四类作为初始分类，不再要求权重百分比。加入轻量标签、项目和可执行子任务。 | 可以完全不组织；用户自己的名称和分类优先保留。 |
| 周期任务 | 支持每日/每周/指定日期系列，实例独立记录结果，不把错过次数无限累加为欠债。 | 说一次重复规则；修改时只在范围不明时问本次还是系列。 |
| 长任务 | 总工作量不再限 24 小时，预计周期不再限 30 天；近期拆成可执行段，远期按里程碑与容量粗排。 | 给目标或截止；细节可后补。 |
| 子任务与依赖 | 明确“先 A 后 B”可作为执行依赖；AI 自己提出的依赖先作为可修正规划假设。 | 明确交付条件；不必维护复杂项目管理图。 |
| 课表导入 | 识别学期、周次和节次；来源级钟点模板集中校准，按来源身份/版本增量更新。不能因标题相似就合并，也不能把新文件缺少某课直接解释为停课或删除。 | 首次校准学期和钟点，之后只看真正不确定或无法判定的变化。 |
| 图片与 PDF | 后续支持图片/OCR，不再把 4 页和固定坐标当永久产品规则；解析过程有内存/大小预算。 | 选取文件；上传模型仅在已授权来源和服务范围内，默认能本地处理的留本地。 |
| 时间边界 | 区分固定、允许、偏好、应急可借用；课程和真实约定固定，软休息可在允许范围移动。 | 一次表达底线；临时变化用一句话说明。 |
| 轨道 | 保留展示与高级编辑；AI 可自行选轨，轨道不再是开始使用规划的必填项。 | 日常无需管理轨道。 |
| 优先级 | 高/普通/低表达重要程度；“固定不动”单独表达可移动性。取消“不可避免”混合两种语义。 | 需要时强调某任务；不要求给所有事项分级。 |
| 自动排程 | 去掉固定 30 分钟量子。用真实分钟边界处理课程，自动布局通常按 5/15 分钟易读步长，手动可到分钟。 | 查看下一步，必要时拖动/说话纠正。 |
| 动态排序 | 取消 AI 最多 ±5 分和固定百分比作为产品硬规则。AI 判断语义、任务重要性和替代方案，本地求解器检查容量/边界并尽量保持稳定。 | 只说明关键目标；原因按需展开，不默认展示黑盒总分。 |
| 自动重排 | 新事项、约束变化、用户延长/完成触发局部修复。近期、正在执行和显式固定项少动或不动。 | 正常情况下不需要批准。 |
| 冲突与过载 | 先自动移动/拆分柔性事项；真做不完时给一个推荐方案及少量替代，保留真实风险。 | 只回答必须由自己作出的取舍。 |
| 执行与专注 | 计时可选；一键开始、自然语言完成、延长或继续。不把计时器当 App 的强制入口。 | 告诉系统真实进展；可以只说一句。 |
| 反馈 | 百分比、耗时、完成内容、延期原因均按需要可选；“剩两题”也能驱动后续安排。 | 不再提交完整反馈表单。 |
| 错过安排 | 旧时段保留安排历史，未知结果不阻塞继续使用；按任务剩余状态统一重排，不逐旧时段复制。 | 可忽略；有空一句话补事实即可。 |
| 复盘 | 自动简报和明日计划；无可靠记录就说明缺口，不强制用户填补。 | 想纠正时说，跳过不会产生新的待办。 |
| 个人化 | 自动计算可追溯统计，持续授权内更新相关摘要和规划估计；数值/样本证据移到详情。 | 用“以后别排这么晚”等语言纠正；可删除记忆或停用。 |
| 提醒 | 开始前、风险、必要的结果询问按作息生成；普通重排只进摘要。截止提醒不再依赖存在当前计划，时间可配置。 | 一次授予系统通知权限和偏好，常态无需处理密集通知。 |
| 历史与撤销 | 从“恢复整份计划”扩展到“撤销这次 AI 操作”，包含相关任务/字段/安排变化；后续用户修改保留。 | 不满意就撤销或一句话纠正。 |
| 备份与恢复 | 完整业务备份含任务、课程、偏好、资料、草稿和历史，并提供实际恢复流程；密钥另受设备加密约束，不承诺跨设备直接还原。 | 主动导出/恢复，或选本地自动备份目录一次。 |
| 外部日历 | 优先只读系统日历作为冲突输入，再做指定日历的受控写入；来源事实不由 AI 随意改。 | 按来源授权一次，避免双份提醒。 |
| 账号/同步/协作 | 取消永久“不做”的产品禁令，但在自动安排可靠后分阶段做。账号不作为读取本地数据的前提。 | 此轮无需新建账号；后续另选是否开启。 |
| 用户名/头像 | 保留当前功能，不增加使用门槛；与完整备份衔接。 | 完全可选。 |
| 现有 UI | 用户已允许围绕自动安排重新组织导航、首页、统一输入、配色和卡片；突出下一行动、结果回执和撤销。 | 现有数据与手动能力可达；减少必经步骤，适配触控、键盘和大字体。 |

### 现有手动能力的兼容去向

- 任务替换、恢复已完成/已取消任务、更正状态/进度/实际耗时继续保留，也能由明确语言指令调用；替换仍保留新旧身份关系，更正仍追加来源记录。
- 手动任务排序、移动时段、移出安排、单步撤销及历史恢复继续可用。自动安排关闭、断网或没有模型时，仍能直接操作，不需要先进入助手。
- 普通未保护任务可按明确指令建立重叠，系统不把重叠当同时执行；固定课表/约定需先有明确变更来源或解除固定。
- 保留已实现的轨道编辑与旧轨道数据；命名、排序、隐藏、锁定统一作为高级组织能力，AI 可代操作。尚未实现的细项排期补齐，不冒称已交付，也不因弱化入口而删除数据。
- 任务筛选、查询、详情、课程/例外编辑、个人资料及本地模型设置入口保留；合并的是反复确认与重复流程，不是取消用户手动接管能力。

## 6．排程器怎样更主动，同时保持稳定

### 6.1 触发与执行

触发源包括已发送的新事项、真实时间约束变化、用户修改、执行结束/延长、可用窗口变化和每日维护。打开页面不反复请求模型；短时间内多个变更合并处理。

本地规则负责快速挪动和容量计算，模型负责意图、估时、拆分、语义排序和复杂取舍。模型返回的动作计划经领域层执行；不把“给模型任意数据库写权限”作为提高 AI 权限的方法。

一次维护先尝试修复受影响的任务与日期，再扩大范围。不为“看起来更优一点”重排整周。不默默扩大截止、挪动当前会话或突破底线。用户明确要求重新安排全周时可扩大范围，仍保留固定承诺。

### 6.2 用户拖动与固定

- 普通拖动意味着“近期按这里做”，不是永久锁死。系统在近期维护中优先保留它，错过后仍可重新安排。
- “固定这个时段”才建立显式保护。过了时间也不能伪造完成；可在历史中保留该固定安排并另排剩余任务。
- “以后晚上别排学习”成为持续时间边界；“我更喜欢白天学习”才是可退让的偏好；“今晚别排”只影响今晚。不要求用户再选一次已经说清的作用范围。

### 6.3 默认参数是可调候选，不再制造一批永久限制

| 参数 | 首版建议起点 | 目的 |
| --- | --- | --- |
| 精排范围 | 未来 7 天，后续按截止与任务需要粗排 | 减少远期日程反复跳动；7 天不是永久上限。 |
| 临近安排 | 默认未来约 30 分钟尽量保持；当前会话始终保留 | 给用户行动稳定性，重大现实变化可提出必要调整。 |
| 空闲容量 | 初期只使用约 80% 可安排时间，剩余作缓冲 | 作为待验证的产品默认，用户可改；不声称是适合所有人的科学比例。 |
| 未知估时 | 按任务上下文给范围或可修正初始值，必要时先安排一个短的探索步骤 | 避免等用户估时；通用估计不冒充个人统计。 |
| 自动化请求 | 事件合并、本地优先、版本缓存；费用上限及失败上限可在高级设置修改 | 让后台执行不变成无限请求；无配置或额度不足降级本地。 |
| 普通变更提醒 | App 内合并摘要，系统通知主要用于行动与显著风险 | 减少打扰；风险未变不反复提醒同一件事。 |

以上数值需要技术样例验证后再冻结，不是本轮已经测试通过的设置。

### 6.4 未知结果的处理

未记录完成不证明没做。系统按“当前可见剩余工作”安排，明确这是排程假设；不追加失败或用户延期反馈。一个任务只维护一份剩余分配，不能每天把旧计划工作量再复制一遍。有真实进展时更新这一份剩余分配；结果未知但已影响重要截止时，再合并询问一次。

反复错过时优先把下一步变小、检查依赖、减少日承诺或建议暂停，取消“每延期一次就不断提高紧急度”的任务债务机制。只有真实截止逼近或用户明确强调重要，才提高紧迫程度。

## 7．少打扰需要的事实、撤销与运行机制

### 7.1 字段来源

同一任务可以有用户原预计、AI 当前规划估计、已记录真实耗时和剩余工作估计。它们可不同，不互相覆盖。缺乏个人样本时仍允许用通用估计安排，标为估计；90 天/3 样本等旧口径仅作为统计实现候选，不阻塞整个规划功能。

“用户说已完成”可以让助手直接执行完成命令；“计时器到了”只能结束该轮目标时长，不能凭空完成任务。若以后存在可靠的明确完成条件，例如全部确认子任务完成，则可以按用户建立的条件自动完成父任务，并记录这一依据。

### 7.2 操作级撤销

每次自动操作记录触发、授权范围、输入版本、被改字段、前后结果和连带安排。提供“撤销这次”以及“恢复这个未来计划版本”两个不同操作。

撤销可逆本地变化时，不能擦掉之后用户明确新增的工作或真实反馈。出现后续修改时，用局部补偿保留新事实；确实无法安全合并才说明具体冲突。更正完成状态是一条新更正记录，不消除原始历史。外部已发送动作不能假装有完整撤销。

### 7.3 少数工程边界保留在内部

- 一次操作整体校验、事务提交、稳定身份、版本检查和幂等防重。
- 文件、网页、课表和模型输出只是输入资料，不提升助手权限。
- 请求只取相关上下文，按分页/检索扩展，不固定因为超过 50 个任务就漏掉重要事项，也不全库直发。
- 同意按用途、服务和数据来源持续有效，不逐请求展示同一发送预览；新增用途、接收服务或扩大来源范围时，集中说明并取得一次授权。同一已授权来源中的新文件不逐个弹同样窗口，明确指令也不能被文件中的文字替代。
- 模型配置、密钥、取消、迟到响应、费用和备份都走真实状态，不能以成功文案代替写入成功。

### 7.4 Android 后台的可实现承诺

前台变更可以立即响应，后台采用事件和系统调度补偿，通知本地调度。不承诺 App 被系统冻结/强制停止后仍每分钟访问远程模型。Android 周期 WorkManager 最小间隔 15 分钟且可能延迟，精确提醒另受权限和系统规则约束；用户看到“上次更新”和尚待处理状态。[WorkManager 官方说明](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest)、[闹钟官方说明](https://developer.android.com/develop/background-work/services/alarms)

## 8．以你的课表为基础的一天

下面是示例对话，不会创建真实任务，也不把 QA 数据用于个人学习结论。

**首次设置**：现有 2026-08-31 开学日期和真实节次钟点继续使用。用户采用一套可用时间，例如工作日晚间和周末某些窗口，启用“AI 自动安排”。系统不把课表外全部时间默认当空闲。

**输入**：“周五交物理报告，英语听力也要练，今晚想跑步。”

系统直接保存事项，把报告拆成少量可执行步骤，给听力和跑步初始估时，在允许窗口内安排。用户看到：“已安排 3 项，报告优先；保留跑步。撤销／查看。”不需要先选新建、逐条采纳时长、再确认全份计划。

**临时变化**：“下午多了一小时实验。”

系统加入临时固定事项，调整受影响的柔性任务。可满足截止时只回执；排不下时只问一个具体取舍：“按目前可用时间，报告还差约一小时。我建议把明天一段弹性时间给报告；也可以减少本周听力安排。”具体时间必须由实际数据计算，此处不伪造你已有安排。

**进展**：“报告写完了，听力只做了一半。”

报告直接完成，听力保留一半已报告进度，剩余自动重排。耗时没说就保持未知，不要求填写额外表单。

**晚上**：自动生成简报和明日安排。用户不看、不复盘，也能继续使用；只有未解决的重要冲突留一张待决策卡。

## 9．实施顺序

用户已经批准的第一批合并了下表原第一、第二阶段所需的最小闭环：**一句话录入自动估时安排、变化自动局部重排、明确语言更新进展、撤销整次操作**。允许配套 UI 重设计；授权不是所有后续能力的实现声明。周期任务、OCR、同步、画像全面自动应用、完整备份恢复及正式 release 全面联网仍后置。后续阶段划分继续作为路线候选。

| 阶段 | 范围 | 完成判断 |
| --- | --- | --- |
| 第一阶段：让助手能执行 | 持续授权、明确命令直接执行、自动保存/估时/排程、内部原子动作、回执＋操作撤销、同源真实事实查询 | 一句话创建并安排/完成/移动任务，无重复批准；撤销和断网路径可靠。 |
| 第二阶段：让计划自己维护 | 自动局部重排、稳定性规则、时间边界分层、错过安排处理、安静摘要和成本控制 | 临时课程/延长/提前结束能自动修复，不移动固定项、不伪造执行。 |
| 第三阶段：补齐日常能力 | 周期任务、轻量子任务/依赖、课表钟点模板/去重/增量、分钟粒度、长任务、完整备份恢复 | 不因旧 4 页/24 小时/30 天等工程限制妨碍正常场景，迁移保留原数据。 |
| 第四阶段：减少长期维护 | 个性化自动应用、按需更深历史检索、只读日历、可选跨设备；托管模型服务单独决策 | 自动化质量、恢复能力、费用和后台矩阵达标后扩大范围。 |

已有大部分可靠的仓储、约束、日志和组件继续复用。旧 REQUIRED 数据迁移时保留原保护，不能因为改名就解锁；旧手动顺序、旧课表钟点、原 API 配置和用户事实也需保留来源。

## 10．验收指标与讨论重点

这些是验收目标，第一批对应范围已获授权，但尚不能据文档认定达成；完成状态以本批实际实现和测试记录为准：

- 普通一句话任务：一次发送后完成录入和允许范围内的安排，不再强制额外确认。
- 临时事件导致的普通冲突：无需手工逐项挪动；回执准确，可撤销。
- 显式完成/取消/恢复命令：对象清楚时一次执行，记录来源，不出现二次审批。
- 部分进度：不要求百分比、耗时、理由都齐全才继续规划。
- 自动操作准确率、用户纠正率、撤销率、无意义重排次数、关键提醒漏发/重复、失败恢复、请求费用均可测；不靠“AI 权限占比 80%”一项数字宣称体验好。
- 真实执行误判、硬边界越界、重复新增、覆盖后续用户编辑、错误外部发送等为严重失败，需专项覆盖。
- 自动化效果先通过隔离技术场景和用户自己体验验证，不重新引入已经移出范围的强制招募/7 天试用。

已经确认：日常自动执行、估时参与安排、局部维护、明确语言更新进展、操作级撤销及配套 UI 重设计。实施不再重复询问这些已批准方向。

仍可继续细化的是个人不可借用/弹性时间的设置方式，以及后续 BYOK 与托管服务路线；没有明确新授权时，沿用已有时间保护和模型数据授权，不因用户同意大方向便扩大到任意数据接收者。
