交付日期：2026-10-17（Asia/Shanghai）。本批实现四条已批准流程及 UI 重设计，不代表 V2 全部候选能力已完成。

后续界面决定：用户要求恢复本轮改动前的 UI，再加入上述功能。原版视觉与默认助手页面已恢复，功能后端保留；当前界面、入口与本轮验证见[原版 UI 恢复记录](ORIGINAL_UI_WITH_AUTONOMY_2026-10-17.md)。下文保留第一轮交付经过与证据。

## 已实现

| 流程 | 当前行为 |
| --- | --- |
| 一句话新增 | 直接保存事项，在已设置的可用时间中安排；未知时长使用标明来源的规划估算。用户明确的时长、钟点和时段优先于模型改写。 |
| 自动维护 | 新事项、进度、时间约束变化及安排开始/结束边界触发局部修复；保留课程、锁定、不可避免安排、当前专注及过去的计划记录。 |
| 明确反馈 | 例如“复习物理完成了一半”“复习物理完成了”直接更新状态及剩余安排，不再逐项确认。不推算未提供的实际耗时。 |
| 整次撤销 | 同时恢复本次任务及安排改动；重启后仍可撤销。后续编辑或执行发生变化时拒绝覆盖；原始反馈日志保留，撤销增加更正记录。 |

“只记着：复习物理30分钟”会保留事项、暂不排程。手动移除后的事项也不会马上被自动补回；明确要求重新安排后才恢复对应范围的补排。

日程、任务、助手和个人设置仍可访问。新助手以统一输入、结果、暂停开关和撤销为主；“详细规划工具”保留原有预览工作流。主题改为暖纸背景、墨绿重点与 sage 辅色，压缩原日程新增入口，并修复反馈提示条遮挡助手底部入口的问题。

## 核心修复

- 查询快捷词“查看待办”按只读查询处理，不再错误新建同名任务。
- “安排明天”“安排今晚”遵循指定日期及晚间窗口。
- 用户明确给出的时长、开始和结束时间不会被模型改标题或估时覆盖。
- 手动拖动、提前放置及修改计划日期优先于旧的录入窗口，不会自动弹回原时间。
- 安排某一天时，保留其他日期手动暂缓的任务。
- 查询卡片使用最新任务状态；已结束或删除的事项从查询结果移除。
- 暂停自动安排后不自动补排其他任务；单独明确的安排命令仍可执行。
- 事务失败不会留下部分事项、半组状态或错误成功回执；重复操作 ID 幂等。

## 当前边界

- 自动维护在 App 打开期间及返回前台时运行；不承诺关闭 App 后持续实时重排。
- 规划以 30 分钟为基本预留单位；例如 45 分钟任务可能预留 60 分钟，这不表示实际工作了 60 分钟。
- 一句话涉及不同日期、无法确定的任务对象或不支持的日期表达时，会保留输入并要求具体化；不会猜测后写入。
- 正在专注时可以直接报告部分进度；完成或取消当前专注任务仍需先结束本轮，以保留计时记录。
- 撤销针对最近一次产生改动的自动操作。后续修改冲突时会拒绝整次回退，而不是抹掉新事实。
- 周期、同步、OCR、新画像自动学习政策、全面分钟粒度与其他远期 V2 能力不在本批交付中。
