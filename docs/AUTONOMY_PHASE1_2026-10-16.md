# 日常自动安排第一批：授权、范围与验收

授权日期：2026-10-16，Asia/Shanghai。交付状态：**第一批实现并于 2026-10-17 完成验收，199 项单元测试与 370 项设备测试通过。** 当前边界、安装状态与证据见[第一批交付记录](AUTONOMY_PHASE1_DELIVERY_2026-10-17.md)。

## 1. 本次已经作出的决定

用户在讨论后同意“日常自动执行，重要取舍按预设规则处理”，并授权继续实现第一批功能。随后用户明确允许撤销此前“本阶段不要大幅改动 UI”的限制，允许围绕自动安排自主设计和修改界面。新授权取代这条阶段性 UI 限制，但不取消数据保护、易用性、真实事实、手动接管和撤销要求。

本批批准的是下面四条完整流程及其必要基础，不是一次性实现 V2 提案的全部能力。批准方向、代码存在、测试通过和已安装交付是四种不同状态。

| 流程 | 目标行为 | 必须保留的边界 |
| --- | --- | --- |
| 一句话录入 → 自动估时并安排 | 用户提交事项后直接创建；缺少时长时采用标明来源的 AI 或本地规划估计，在已采用的可用窗口中安排；明确说“只记着”时不安排。 | 不能把估计伪装成用户输入，不能假设课表外全部可用，重复提交不重复新增。 |
| 临时变化 → 自动局部重排 | 新事项、约束变化、用户延长或明确提前完成后，优先修复受影响的普通安排；超出容量时保留未排入事项并说明风险。 | 固定课程、明确承诺、显式锁定、正在执行的会话受到保护；不自动改真实截止，不以重排制造执行延期事实。 |
| 一句话报告进展 → 更新状态及剩余安排 | 对象与范围清楚的“完成了”“做了一半”“取消这个”等指令直接执行，保留用户声明来源；只追问会实质改变结果的歧义。 | 时间经过、通知被忽略、计时目标结束都不能当成完成或失败；没有提供的耗时和进度保持未知。 |
| 不满意 → 撤销整次操作 | 一次撤销同时恢复这次相关字段、任务和安排变化，并保留操作记录。 | 不能覆盖操作之后的用户修改、真实执行和固定承诺；冲突时保留当前事实，说明哪些部分不能直接恢复，不盲目套用旧快照。 |

## 2. 执行与用户参与

普通日常动作不再要求逐次经过“阅读建议—采纳字段—查看草案—确认写入”。明确用户命令本身是相应动作的授权；持续自动安排在用户启用的范围内执行，随时可以暂停或改为仅建议。产品首次启用和数据发送说明不是每次动作的审批。

只有重大歧义、需要突破固定承诺或作息底线、改变真实截止、越过数据服务授权等情况才提出一个具体问题。普通柔性任务之间的移动、拆分、顺延和容量取舍由系统处理，结果通过简短回执、原因和撤销呈现。

内部动作仍须经过当前任务、约束和执行状态校验；提交具有版本检查、原子性和幂等保证。失败或过期不能留下半组任务、部分计划或错误成功回执。远程响应迟到时不得覆盖之后的用户操作。

## 3. 本批 UI 授权与后续调整

2026-10-16 曾允许重新组织首页、统一输入、任务与日程信息、AI 执行回执和撤销入口。

2026-10-17 用户查看后要求“把 ui 界面恢复原版，然后再加入这些功能”。此决定取代上一轮自主重设计方向：以 `2026-10-16-before-ai-autonomy-phase1/workspace-source.zip` 为精确视觉基准，恢复配色、字体、卡片、导航及主要布局；原版安排助手为默认页，新增“一句话处理”入口及可展开的自动安排/撤销控件。四条功能授权及数据保护边界继续生效，不回退功能后端。

同日后续调整：用户要求助手仅保留一个功能，移除其底部标签，改为日程页右下角的同款悬浮按钮。当前以精简“一句话处理”弹层替代旧助手页面；只保留统一输入、处理结果和结果撤销，自动安排开关移至我的设置，时间与课表仍从我的设置访问。

我的页随后进一步收拢：主页面保留用户名、头像、数值画像及相关文字记录；其余版本、自动安排、提醒、时间、计划历史、模型服务、类别偏好和数据管理移至独立设置页。设置页返回主我的页面，时间设置返回设置页。

界面应突出下一行动和结果，减少重复入口与表单。已有任务查询/编辑、课表与例外、个人资料、模型配置和手动接管能力仍需可达；不能以重新设计为由丢失已有数据、功能或可访问性。窄屏、大字体、深色、键盘、导航恢复和触控可用性继续属于验收范围。

## 4. 第一批不包含的远期能力

周期任务模板、完整子任务/依赖系统、OCR、新课表来源级增量导入、长任务和分钟粒度全面改造、画像全面自动应用、完整跨设备备份恢复、外部日历、账号/同步/协作、托管模型服务及正式 release 全面联网，仍是后续候选或单独交付事项。现有已实现能力继续保留。

第一批可复用现有本地规则和联网适配器。没有模型、关闭远程 AI 或请求失败时仍可使用本地任务及基础排程；本地估计必须明确其来源，不冒称经过真实模型判断。Android 后台执行受设备调度条件影响，不承诺任意状态持续实时运行。

## 5. 对历史 C01–C07 的影响

这里的编号来自 [2026-10-06 一致性决定](CONSISTENCY_REVIEW_2026-10-06.md)，不是 283 条清单中重复出现的 C 类编号。原报告和审计证据保持不变。

| 历史决定 | 本批状态 | 新规则 |
| --- | --- | --- |
| C01 到点只提醒，主动开始/明确补录才记录执行 | 保留 | 自然语言明确开始/完成/进展也属于用户操作；不再要求同一命令后再点一次确认。 |
| C02 普通重叠须明确，保护不能被直接覆盖 | 保留 | 自动规划不制造并行高专注工作；用户明确提出的重叠可按现有领域校验执行，受保护边界仍不可暗中突破。 |
| C03 恢复只影响排序/安排，执行纠正独立 | 保留并补充 | 计划历史恢复保持原义；新增“操作撤销”可以针对明确操作纠正其字段/状态/安排，但不能回退之后的新事实，二者不能混用。 |
| C04 简单录入、未知保留、建议确认后生效 | 部分取代 | 简单录入、来源和真实未知保留；AI/本地规划估计可直接用于安排，不需要逐字段采纳，不作为用户输入或实际耗时。 |
| C05 草案持久保存、确认前校验、不确认不写正式计划 | 部分取代 | 保留可恢复的仅建议/手动草案及应用前校验；授权内动作可直接提交，不强制生成用户必审草案。 |
| C06 单一模式、兼容旧三模式数据 | 保留 | 自动安排开启/暂停/仅建议是授权行为选择，不恢复旧三类用户参与模式。 |
| C07 高/中/低/不可避免及跨路径保护 | 兼容保留，语义拆分后置 | 本批不能因扩大权限自动解除旧 REQUIRED/不可避免的时段保护；“重要性”与“固定性”分离是后续迁移方向，须单独验证数据兼容。 |

旧“AI 只能建议”“每次先预览再确认”和“AI 最多 ±5 分”不再作为本批产品权限上限。现有确定性评分可以作为基础实现继续复用；取消产品上限不等于本批已完成新的排序模型。

## 6. 验收目标与证据

下列目标已由本批新增测试及完整回归验证，具体边界和未执行的真实联网测试见交付记录；此前 Bug 修复测试没有被当作新功能的单独通过证明。

- 一次提交能创建并安排，缺估时有可辨来源；无可用窗口时保留任务并说明原因。
- 新事项/进展/约束变化能局部维护，保留固定项和当前会话，不产生重复任务与重排循环。
- 明确状态命令一次执行；歧义不误写；时间经过不自动产生任务结果。
- 整次撤销可恢复相关改动；后续编辑或执行发生后不会被旧操作覆盖。
- 过期版本、失败、取消、重试和应用重启不留下部分提交；回执与真实保存结果一致。
- 原有课表钟点、学期、任务、计划、个人资料及模型配置保持；重设计后的常用与手动入口可用。
